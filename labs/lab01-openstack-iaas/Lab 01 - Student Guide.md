# Lab 01 - OpenStack IaaS Liftoff: Enterprise Provisioning and Governance

* **Program:** MBA in Cloud Computing & Infrastructure
* **Environment / Platform:** Red Hat Academy (CL110 / Red Hat OpenStack Platform)
* **Technical Stack:** OpenStack CLI (`python-openstackclient`), Horizon Dashboard, QEMU/KVM
* **Estimated Duration:** 40 to 45 minutes

---

## 🎯 Lab Objective

Empower students to operate an enterprise private cloud by understanding the full lifecycle of an IaaS instance (compute, SDN networking, and block storage).

**Enterprise Business Scenario (FinCorp):**  
The treasury engineering team at *FinCorp* requires an isolated Linux virtual machine (`finance-server1`) to run nightly automated settlement and reconciliation jobs. The instance must be provisioned within the dedicated audit network (`finance-network1`) and verified both through automation scripts (CLI) and the corporate web dashboard (Horizon).

**Key Skills Acquired:**
1. Initialize controlled training environments from the primary management workstation.
2. Authenticate against the OpenStack control plane using project RC environment files (`developer1-finance-rc`).
3. Audit compute sizing profiles (Flavors) and OS image catalogs (Glance).
4. Provision virtual instances via CLI ensuring proper binding to SDN segments (Neutron).
5. Inspect serial boot logs and troubleshoot hypervisor events (Nova).
6. Visually inspect topology maps and instance health on the Horizon Web Dashboard.

## 🚀 Step-by-Step Guided Walkthrough

### Step 1: Initialize the Lab Environment

From the `workstation` terminal, trigger the automated preparation script to scaffold required project networks and images:

```bash
lab intro-launching start
```

> **Expected Output:**

> SUCCESS: Environment is ready for the lab.
> ```

---

### Step 2: Authenticate to the OpenStack Control Plane

OpenStack CLI commands interact directly with the **Keystone** identity service. Source the project RC credentials generated by the lab script for your user:

```bash
source ~/developer1-finance-rc
```

Confirm that your session token has been successfully issued:

```bash
openstack token issue
```

> **Why this matters in Enterprise:**  
> In modern production environments, Cloud Engineers utilize Service Principals or Application Credentials in CI/CD pipelines and Terraform automation instead of interactive passwords.

---

### Step 3: Audit Cloud Infrastructure Catalogs

Before dispatching virtual machine deployments, audit the resource catalogs:

1. **Operating System Image Catalog (Glance):**
   ```bash
   openstack image list
   ```
   *Identify the enterprise-hardened `rhel8` image.*

2. **Compute Hardware Sizing (Nova Flavors):**
   ```bash
   openstack flavor list
   ```
   *Inspect the `default` flavor and review allocated vCPUs, RAM, and root disk volume.*

3. **Private Network Segmentation (Neutron Networks):**
   ```bash
   openstack network list
   ```
   *Locate the dedicated `finance-network1` provisioned for the finance department.*

---

### Step 4: Deploy the Virtual Instance (`finance-server1`)

Issue the creation command to the Nova compute API, binding the OS image, compute flavor, and private network:

```bash
openstack server create \
  --image rhel8 \
  --flavor default \
  --nic net-id=finance-network1 \
  --wait finance-server1
```

> **Operational Insight (`--wait` flag):**  
> The `--wait` flag forces synchronous execution, blocking the CLI until the instance transitions from `BUILD` to `ACTIVE` across the Nova scheduler and KVM hypervisor.

---

### Step 5: Serial Console Inspection and Verification

Query instance status and examine the serial boot log to verify kernel initialization and cloud-init execution:

1. **Verify Instance State:**
   ```bash
   openstack server list
   ```

2. **Examine Serial Console Boot Log:**
   ```bash
   openstack console log show finance-server1 | tail -n 25
   ```

> **Expected Output:**
> Complete `cloud-init` configuration logs followed by the standard Red Hat Enterprise Linux 8 login prompt.

---

### Step 6: Visual Validation in the Horizon Dashboard

1. On the `workstation`, open **Firefox**.
2. Navigate to:  
   `http://dashboard.overcloud.example.com`
3. Enter authentication details:
   * **Domain:** `Example`
   * **User Name:** `developer1`
   * **Password:** `redhat`
4. In the left navigation tree, select: **Project $\rightarrow$ Compute $\rightarrow$ Instances**.
5. Locate `finance-server1`, confirm its status is `Active`, and verify assigned IP addresses.
6. Click on the instance name and open the **Console** tab to observe the interactive graphical terminal.
